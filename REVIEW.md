# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72-74) | Unconditionally returned `{"status": "ok"}` without checking if MongoDB was reachable. | Shut down MongoDB or provide an invalid `MONGO_URI`; endpoint returned 200 instead of required 503. | Pinned connectivity check with `client.admin.command('ping')` inside a `try/except` block, raising HTTP 503 on failure. |
| 2 | `compute_late_minutes` (lines 33-37) | Checked `minutes > 10` after integer truncation, returning 0 for `09:40:01` (601s elapsed // 60 = 10, but `10 > 10` is False). Also lacked overnight shift handling and timezone awareness. | Punch-in at `09:40:01` with `09:30` shift start returned 0 instead of 10. | Replaced with `elapsed_seconds > 600`; returns `elapsed_seconds // 60`. Corrected timezone calculation and overnight shift date alignment. |
| 3 | `compute_work_hours` (lines 40-41) | Used Python's built-in `round(..., 2)` which applies banker's rounding (round-half-to-even) rather than the required `ROUND_HALF_UP` arithmetic. | Input yielding exactly half-way value like 4.495 hours rounded to 4.49 instead of 4.50. | Implemented exact decimal arithmetic using `Decimal` quantized with `ROUND_HALF_UP`. |
| 4 | `compute_overtime` (lines 44-47) | Did not enforce the minimum 30-minute threshold; returned overtime for 1 to 29 minutes. Also anchored `shift_end` to `date_str` calendar date, failing for overnight shifts. | Punch-out at 18:35 for 18:30 shift end returned 5 minutes overtime instead of 0. | Added threshold check `elapsed_sec >= 1800`; for overnight shifts, anchored `shift_end` to `attendance_date + 1 day`. |
| 5 | `create_employee` (lines 77-85) | Concurrency race condition via check-then-insert (`find_one` then `insert_one`). Missing input validations (regex on `emp_code`, `shift_start != shift_end`). Serialized `created_at` as datetime object instead of epoch ms. | Concurrent requests with same `emp_code` both succeeded or crashed with unhandled errors; responses returned datetime objects. | Enforced database unique index on `emp_code`, caught `DuplicateKeyError` to return HTTP 409, added model validation, and serialized `created_at` as epoch ms. |
| 6 | `list_employees` (lines 89-96) | Off-by-one pagination bug (`skip = page * page_size` skipped the first page completely at `page=1`). `total` counted the whole collection ignoring department filter. Missing sort order. Missing pagination parameter constraints. | Requesting `page=1&page_size=20` skipped items 0-19; filtering by department reported collection-wide total. | Changed skip calculation to `(page - 1) * page_size`, filtered `total` with query `q`, sorted by `emp_code` ascending, and added constraints `page >= 1`, `1 <= page_size <= 100`. |
| 7 | `punch_in` (lines 100-121) | Check-then-insert race condition. Missing employee existence check resulting in 500 `TypeError` on missing employee. Injected unauthorized `id` field. Did not truncate instant to seconds (R1). Derived date via naive `ts.date()` ignoring IST and overnight shifts. | Concurrent punch-ins caused duplicate records or crashes; unknown `emp_code` produced 500 error; punch at 01:15 IST for 22:00-06:00 shift got wrong attendance date. | Validated employee exists (404), truncated timestamps to whole seconds (R1), derived attendance date in IST accounting for overnight shifts, enforced unique composite index `(emp_code, date)` returning 409 on duplicate, and removed `id` field. |
| 8 | `list_attendance` (lines 124-150) | Loaded entire collection into Python memory (`list(db.attendance_logs.find(q))`), sorting and slicing in Python (catastrophic at 100k docs). Missing `date_from > date_to` validation (422). Injected unauthorized `id` field. Failed to serialize BSON dates to epoch ms. | Querying 100k documents exhausted memory and took seconds; passing `date_from > date_to` returned empty list instead of 422. | Pushed sorting `[("date", -1), ("emp_code", 1)]` and `.skip().limit()` into MongoDB, validated date range with 422, removed `id`, and serialized all instants to epoch ms. |
| 9 | Database Indexes (line 22) | No indexes created at application startup; all queries, lookups, and sorts performed full collection scans (`COLLSCAN`). | Explain output showed `COLLSCAN` across all queries; listing was slow on large datasets. | Configured FastAPI `lifespan` handler to idempotently create compound and unique indexes on `employees` and `attendance_logs`. |
| 10 | Instant Representation & Types | Mix of naive datetimes, seconds, and BSON dates across requests and responses violating OpenAPI requirement for integer epoch milliseconds. | Sending float or seconds timestamps was accepted; responses returned ISO strings or datetime objects instead of epoch ms integers. | Added strict integer bounds validation (`100000000000 <= ms <= 4102444800000`) and bidirectional serializer converting to/from BSON UTC datetime. |

### Inspected and Determined Not to Be Defects
- **FastAPI Routing & Structure**: The endpoint routing pattern, dependency injection, and Pydantic base model structure in the starter file were clean and appropriate for a single-file FastAPI architecture.
- **HTTP 201 Created**: Returning HTTP 201 for successful resource creation on `POST /employees` and `POST /attendance/punch-in` is compliant with REST best practices and the OpenAPI specification.
- **Default Status `PRESENT`**: Defaulting `status` to `PRESENT` when omitted in punch-in aligns with business rule R6 and the OpenAPI contract.
